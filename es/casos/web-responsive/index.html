WEB RESPONSIVE

Diseño de interfaces para múltiples dispositivos.

Diseño UI y maquetación · Mobile-first · 2019–2024 · 1 portal corporativo, 1 componente de aplicación y 4 sitios web.

Nota de archivo

Proyectos realizados entre 2019 y 2024, mostrados a partir de los diseños originales. Varios sitios han cambiado desde entonces o ya no están publicados, por eso no se enlazan. Los nombres de clientes se omiten.

Lo que se muestra es el criterio de adaptación entre anchos, no el estado actual de cada web.

Criterios y métodos

Diseño y maqueto partiendo de la columna móvil: primero se decide qué contenido va delante y qué puede esperar; cada ancho mayor añade columnas, amplía imágenes o muestra navegación que en móvil está plegada. La adaptación se define en el diseño, no se deja a la maquetación: cada componente tiene sus saltos y su comportamiento documentados. Tres anchos de referencia:

375 Móvil · una columna, navegación plegada en menú
768 Tablet · dos columnas donde el contenido lo admite
1440 Escritorio · rejilla completa y navegación visible

Tecnologías base

Tokens de diseño Variables CSS para color, tipografía, espaciado y radios. Un cambio de marca o de tema se hace en un solo sitio y llega a todos los componentes.
Media queries Saltos definidos por el contenido, no por dispositivos concretos. Escritas de menor a mayor ancho (min-width), en orden mobile-first.
Container queries El componente responde al ancho de su contenedor, no al de la pantalla: el mismo bloque funciona en una columna lateral o a ancho completo.
CSS Grid Rejillas de página y de galería con columnas flexibles (fr, minmax, auto-fit) que se reorganizan sin duplicar marcado.
Flexbox Alineación y reparto de barras, menús, formularios y grupos de controles, con gap en lugar de márgenes sueltos.
Escala fluida clamp() y unidades relativas (rem, %, vw) para que texto y márgenes crezcan entre saltos sin cambios bruscos.
Imágenes adaptativas srcset, picture y object-fit para servir el recorte y el peso adecuados a cada ancho y densidad de pantalla.
Uso táctil Zonas de pulsación de 44 px como mínimo, 16 px de texto en campos de formulario y contraste suficiente en todos los anchos.

Validación en las herramientas de desarrollo del navegador y en dispositivos reales, en ambas orientaciones.

Diseño de componentes

Barra de herramientas con opciones personalizables para software corporativo: una aplicación web de alta complejidad y densidad de datos. El ejercicio muestra cómo se diseña un componente teniendo en cuenta desde el inicio su comportamiento responsive: una sola estructura con tres vistas —escritorio, tablet y móvil— que se activan en saltos de ancho establecidos.

La estructura tiene tres bloques. A y C tienen ancho fijo; B ocupa el centro y crece según lo necesita. B agrupa acciones, accesos directos y notificaciones, separados entre sí, y es personalizable: desde el menú de usuario cada persona añade o quita accesos y se suscribe al canal general o a canales concretos de notificación. Su longitud no es predecible. El logo ocupa una fila superior propia: al estrecharse la barra, los iconos avanzan bajo el logo hasta el menú antes de agruparse.

Control de calidad

Reducir la barra no convierte el móvil en un dispositivo apto para todo. Algunas operaciones y procedimientos de negocio necesitan una interfaz amplia; qué tareas se ofrecen en cada dispositivo se revisa como medida de control y calidad dentro del flujo de diseño.

Experiencia

Diseño y construyo layouts responsive para aplicaciones y sitios web en tres contextos de trabajo:

Frameworks Angular

Layouts de aplicación con barras, paneles laterales, formularios y tablas de datos; componentes con estilos encapsulados que se adaptan entre escritorio, tablet y móvil.

Vanilla HTML, CSS y JavaScript

Sitios y prototipos sin dependencias, a partir de tokens, grid y flex, con scripts ligeros solo para comportamientos concretos.

CMS Joomla, Drupal y WordPress

Plantillas y temas responsive, adaptación de temas existentes y maquetación de contenidos que edita el propio cliente.

En todos los casos la decisión responsive fue de contenido antes que de maquetación: qué se ve primero, qué se pliega y qué cambia de forma.
