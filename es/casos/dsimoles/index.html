DSimoles: un framework para sistemas de diseño y el DS del ecosistema iMoles

Lo que se expone aquí son dos cosas a la vez: DSBook, un framework reutilizable para definir, documentar y dar seguimiento a un sistema de diseño, y DSimoles, el sistema de diseño del ecosistema iMoles para aplicaciones médicas con accesibilidad WCAG 2.1 AA, construido con ese framework.

El punto de partida es el prototipo de la revisión del proyecto iMoles: de él salen los productos, los requisitos y los componentes que el sistema de diseño tiene que cubrir. El framework se abre aquí mismo, en el navegador, con todo su contenido.

Qué se expone

El repositorio de DSimoles contiene dos capas que se pueden leer por separado: el método y el sistema que se obtiene al aplicarlo.

Framework

DSBook

Un workspace para definir, documentar y seguir un sistema de diseño, pensado para reutilizarse en otros proyectos.

  • Guía de definición con una subsección por decisión y sus criterios de aceptación.
  • Matriz de seguimiento con estados (Ready, In process, Pending, Not applicable) y review registrada.
  • Contenedor de documentación en HTML estático, sin build ni servicios externos.
  • Ciclo de trabajo entre Claude Design, Claude Code y Git, con protección contra la pérdida de trabajo.

Sistema de diseño

DSimoles para el ecosistema iMoles

El sistema de diseño de las aplicaciones médicas del ecosistema iMoles, definido con el framework.

  • Tokens primitivos y semánticos, con temas.
  • Componentes base y patrones, más componentes de producto propios de iMoles (por ejemplo, la insignia de riesgo, la fila de captura o el resumen de análisis).
  • Accesibilidad WCAG 2.1 AA como requisito, no como extra.
  • Gobierno: cómo se añade, cambia o depreca algo del sistema.

Punto de partida

De dónde sale

El punto de partida inicial es el prototipo de la revisión del proyecto iMoles.

Ese prototipo navegable de la app de prediagnóstico dermatológico fija los productos, los flujos y los requisitos que el sistema de diseño tiene que servir. DSimoles no parte de un catálogo genérico de componentes: parte de lo que esa propuesta necesita y lo generaliza donde tiene sentido.

Por eso conviven en el sistema los componentes base y los específicos de iMoles, y por eso el contenido de la guía (usuarios, productos, requisitos) se escribe a partir de ese caso.

Cómo se trabaja

El repositorio es la fuente de verdad. El diseño y la implementación se reparten entre dos herramientas y una persona que valida.

  1. 1 GitHub. Es la única fuente de verdad del sistema.
  2. 2 Claude Design. Lee el repositorio, diseña y construye las páginas de cada sección.
  3. 3 Claude Code. Trae los cambios, los integra en local y ejecuta las comprobaciones del contrato de datos y de las pruebas.
  4. 4 Validación. La persona responsable revisa en local; sin su visto bueno no se sube nada.
  5. 5 Registro. Cada integración queda en el changelog y se avisa a Claude Design para que siga desde la nueva base.

Estado

De las 175 subsecciones de la guía, 25 están en Ready con una review registrada, 46 están en proceso, 1 está pendiente y 103 se han marcado como no aplicables, cada una con un motivo explícito.

Una página existente no implica Ready: ese estado exige una review registrada, no una certificación automática.

Las cifras corresponden a la versión 0.29.0 del proyecto (2026-10-15) y cambian con cada integración.
